# design-sync NOTES

## Fixes (symptom → root cause → fix)

- **[GENERAL] Converter found 0 exported components / `[TITLE_UNMAPPED]` on all 14 titles** → `packages/ui/package.json` has an `exports` map but no `types`/`typings` field, so the converter's `.d.ts`/export-name scan (`findTypesRoot`) fell back to a nonexistent `packages/ui/index.d.ts` and returned zero symbols → added `"types": "./src/index.ts"` to `packages/ui/package.json`. This is also a genuine, correct addition for the real package (not just a sync-tool workaround) — nothing else in the repo declared a `types` field, and this is the accurate entry point.
- **[GENERAL] `story sources: 0/0 stories paired to module exports`** → `.design-sync/config.json`'s `storybookConfigDir` was set to `apps/docs` (the package dir) instead of `apps/docs/.storybook` (the actual Storybook config dir) → story `importPath` resolution (relative to `dirname(storybookConfigDir)`) pointed one level off and never found the story source files → fixed `storybookConfigDir` to `apps/docs/.storybook`. After the fix: 132/132 stories paired.
- **[GENERAL] Half of every component's rendered elements were invisible in the compiled preview (but NOT in the real Storybook)** → `packages/tailwind-config/base.css`'s `.squircle` utility used `mask-image: paint(squircle)` (CSS Houdini Paint API), which requires the CONSUMING app to register a paint worklet via `CSS.paintWorklet.addModule(...)` (previously done only by `apps/web/src/components/SquircleRegistry.tsx`, itself only mounted in `apps/web`'s Next.js layout). The design-sync preview page has no such registration, so `mask-image: paint(squircle)` referenced an **unregistered** paint function — Chromium then renders the element's mask as fully transparent (invisible), except specifically for elements that also had `backdrop-filter` (e.g. `tone="ghost"` buttons), which apparently bypass/ignore the broken mask when forced onto their own compositing layer. Confirmed via a headless Playwright test: disabling `mask-image` on `.squircle` fixed every hidden element instantly. **Fix: implemented [ADR 0002](../docs/decisions/0002-native-corner-shape-squircle.md) now** (it had been "proposed, not yet done") — replaced `.squircle`'s Houdini paint with native `corner-shape: squircle`. Removed `apps/web/src/components/SquircleRegistry.tsx`, its usage in `apps/web/src/app/layout.tsx`, `apps/web/public/worklets/squircle.js`, `apps/docs/public/worklets/squircle.js`, and the worklet-registration snippet in `apps/docs/.storybook/preview.ts`. This is not just a sync-tool fix — it means ANY consumer of the compiled bundle (including a Claude Design agent building with these components) would have hit the same silent invisibility bug; the old approach was fragile by construction (registration must happen in every consuming context, forever).
- **`[GRID_OVERFLOW]` (wide) on Button, Divider, Input, Skeleton, SquircleBox** → some stories (`Hierarchy`, `Intent X Tone`, `Form`, multi-input rows, nested/sized boxes) render wider than a grid cell → applied `cfg.overrides.<Name>.cardMode: "column"` for all five in one batch.
- **`[ASSETS_BLOCKED] invalid-url.com` on Avatar** → NOT a real network-sandboxing false-positive here — Avatar's `Image Error` story deliberately passes `src: "https://invalid-url.com/image.jpg"` to test the fallback-to-icon UI (see `Avatar.stories.tsx`). Both panels correctly show the same fallback icon regardless of network access. Graded `match` normally.
- `[FONT_REMOTE]` "Inter", "JetBrains Mono" — informational only (not `[FONT_MISSING]`); fonts are loaded via `next/font/google` in the real app and via a remote `@import` scraped from the storybook build for this sync. Not blocking; revisit if a future sync reports `[FONT_MISSING]` instead.
- `tokens: 60 defined, 37 referenced (1 missing, below threshold)` — one design token appears unused/unreferenced; below the warning threshold, not investigated further this sync.
- **[GENERAL] `SquircleBox` removed entirely** (post-first-upload) — now that `corner-shape: squircle` is a plain base-CSS class (`.squircle` + any `rounded-*`), a dedicated wrapper component whose sole differentiator was applying that shape is redundant; any element can opt in directly. Removed `packages/ui/src/components/atoms/SquircleBox/`, its export from `packages/ui/src/index.ts`, and the stray reference in `packages/ui/src/tokens/colors.ts`'s comment. Roster is now 13 components, not 14. `docs/ui-component-inventory.md`'s AssetCard molecule spec referenced `SquircleBox(elevated)` as a building block — update that to `squircle rounded-2xl shadow-studio` directly next time that doc is touched.
- **[GENERAL] `corner-shape: squircle` doesn't degenerate to a sharp corner at `border-radius: 0`** → Button's `ButtonGroup` story (`rounded-none` on the inner segments of a joined group, to get sharp internal dividers under one smooth outer shape) still rendered a visible curve on every "sharp" edge in Chromium — a real limitation of this experimental property, not a fallback-support gap (Chromium DOES support `corner-shape`, it just doesn't fully degenerate at radius 0). Confirmed via computed styles (`border-radius: 0px`, `corner-shape: squircle` — both correctly set, yet still visibly curved) and a headless screenshot A/B. **Fix:** added `.squircle.rounded-none { corner-shape: round; }` to `packages/tailwind-config/base.css` — any future composition that forces an element's radius to zero while sharing the `.squircle` base class gets this automatically, no per-callsite class needed.
- **Claude Design flagged Tailwind's internal `--tw-*` custom properties (`--tw-translate-x`, `--tw-rotate`, etc.) being cataloged as design tokens** — investigated whether the sync config can filter these out before upload: **it cannot, in this converter version.** `_ds_bundle.css` for this DS comes entirely from the `[CSS_FROM_STORYBOOK]` fallback (scraping the full compiled Tailwind output), because this DS has no separate tokens package/CSS and no `cfg.tokensPkg`/`tokensGlob` configured — there's no config-level token-exclusion knob (checked `CONFIG_KEYS` in `.ds-sync/lib/common.mjs`; no such field exists). The deeper reason `/* @kind */` annotation (Claude Design's other suggestion) doesn't apply either: this DS's real design tokens are Tailwind **class names** (`bg-primary-500`, `shadow-studio`, `intent`/`tone` props), never expressed as CSS custom properties — `packages/ui/src/styles/tokens.css` is an explicit unused placeholder saying so. The `--tw-*` variables are Tailwind's own internal plumbing (transform/ring/shadow composition) and are functionally required in the shipped CSS — stripping them would break rendering (e.g. `active:scale-[0.98]`, `shadow-studio`, `backdrop-blur-md` all depend on them). This is cosmetic clutter in Claude Design's token browser, not a rendering defect, and isn't fixable from this repo without inventing a parallel, redundant CSS-custom-property token system this DS doesn't otherwise use (real drift risk, not worth it for a documentation-only benefit). Flag upstream to whoever maintains the design-sync skill/converter: a `cfg.tokenExclude` (name-pattern) knob, or having Claude Design's own token cataloger ignore `--tw-*`-prefixed names, would both resolve this without repo changes.

- **[GENERAL] `success`/`warning`/`error`/`info` Tailwind color scales were only PARTIAL (50, 100, 500, 600, 700, 800 — missing 200/300/400/900/950)** — didn't matter while the atoms only ever referenced the 500/600/700 shades directly, but broke silently the moment `Button`'s solid tone was upgraded to a light→base gradient (`from-error-400 to-error-500`): Tailwind's JIT only generates a utility for a shade that exists in `theme.extend.colors`, so `from-error-400` compiled to nothing, `--tw-gradient-from` was never set, and the button rendered with a fully transparent background — no build error, no warning, just an invisible fill. Confirmed via computed styles (`background-image: none` despite the class being present in `className`). **Fix:** completed all four scales to the full 50–950 ramp in `packages/tailwind-config/tailwind.config.js`, matching `packages/ui/src/tokens/colors.ts` (which already had the complete ramps — the drift was tailwind-config-specific). **Lesson for future components:** a color scale that "has enough shades for what's used today" is a trap — any new composition (gradients, ring offsets, arbitrary shade references) can silently need a shade nobody thought to add, with zero build-time signal. Keep every semantic color alias at the full 11-step ramp, always.
- **[GENERAL] The reference preview's (`premium-studio-preview.html`, the published Artifact) `.tone-solid` used a `linear-gradient` + 3-layer `box-shadow` (inset highlight + two tinted outer shadows) — the real `Button.tsx`/`IconButton.styles.ts` only had a flat `bg-{color}-500` + single soft `shadow-studio`.** The two were never actually diffed against each other before this point in the sync — Storybook-vs-preview compare only proves the compiled bundle matches ITS OWN Storybook render, never that the _design intent_ (the Artifact) is what the code produces. Caught only because the user compared the artifact's raw CSS against the rendered Button HTML by hand. **Fix:** rewrote the `solid` tone's `compoundVariants` in both `Button.tsx` and `IconButton.styles.ts` to a `bg-gradient-to-b from-{c}-400 to-{c}-500` + the same 3-layer arbitrary-value `shadow-[...]` per intent/colorScheme (shadow tint = that intent's own 700-shade RGB, at ~0.35-0.4 opacity — matches the Artifact's `--c-shadow` derivation for `primary`/`danger` exactly, since `primary-700`/`error-500` happen to equal the Artifact's hardcoded hex). Also added the missing ambient shadow to `ghost` tone, and swapped the base transition from generic `transition-all` to an explicit spring easing (`ease-[cubic-bezier(0.34,1.56,0.64,1)]`) matching the Artifact's `.btn2` transition — the UX spec's "Soft Scale Feedback" always called for spring physics, not a linear ease. **This is the real gap a compare-oracle-only workflow can't catch: re-verify against the ORIGINAL design reference (artifact/spec), not just Storybook-vs-preview self-consistency, whenever "does this look premium enough" is in question.**
- **Stray uncommitted local edit found mid-session: `Button.stories.tsx`'s `ButtonGroup` story was missing from the working tree**, despite being present in the last real commit (verified via `git diff HEAD`) — not something this sync session's own edits touched. Restored via `git checkout HEAD -- <path>`. Cause unknown (possibly concurrent editing outside this session — a branch switch + PR merge to `main` was independently observed mid-session too). **If a story silently vanishes from a capture again, `git diff HEAD` on that story file before assuming the sync tooling is at fault.**

## Re-sync risks

- The `types` field addition to `packages/ui/package.json` and the `storybookConfigDir` fix are both config/repo-level — they should carry forward automatically on re-sync, but if `packages/ui`'s `exports`/build setup changes (e.g. a real `dist/` build gets added later), re-verify `cfg.entry` still points at the right place.
- The squircle CSS fix is now the actual product behavior (not sync-specific) — if `.squircle` ever gets a JS-based implementation again in the future, re-test this exact failure mode (elements with `mask-image`/similar referencing an unregistered function silently vanish outside the one context that registers it).
- Avatar's `Image Error` story's `[ASSETS_BLOCKED]` warning will reappear on every re-sync — that's expected and fine; do not chase it as a new issue.
- Roster is 13 components (not 14 — `SquircleBox` removed, see above). `Button` was graded exhaustively across all 13 of its stories (not just the `[STORY_CAP]`-limited first 6) after the `ButtonGroup` bug was found and fixed — raise `--max-stories` the same way for any other component before trusting `sibling-trusted` grades on a component with more than 6 stories and a visually distinct one past the cap (icon groups, joined/segmented compositions, anything with a `rounded-none`-style override are the pattern to watch for, per the corner-shape bug above).
- The project already has files this sync never uploaded (`fonts/`, `fonts/fonts.css`, `_adherence.oxlintrc.json`, `_ds_manifest.json`) — Claude Design's own app added these after ingesting an earlier upload (self-hosted the fonts, generated its own manifest/lint config). **Do not delete these in a future reconciliation pass** — the reconciliation deletes in this sync were scoped by hand to only the specific paths known to be orphaned (`SquircleBox`'s files), explicitly avoiding a blanket "delete anything my local build doesn't produce" sweep that would have wiped them.
- Claude Design's token browser will keep showing `--tw-*` entries — this is expected per the finding above (no config fix exists for it), not a regression to chase on future syncs.
